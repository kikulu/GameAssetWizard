# 多語系與翻譯指南

介面文字、標籤庫、模式名稱、尺寸預設與創作範本都已分拆成各語系檔案。目前支援 **繁體中文（zh-TW）**、**English（en）**、**日本語（ja）**、**한국어（ko）**。

## 語系檔結構

```text
locales/
├── locales.json              # 語言清單、預設語言（zh-TW）與後備語言（en）
└── <語言代碼>/
    ├── ui.json               # 介面文字（扁平：鍵 → 字串）
    ├── profiles.json         # 六種模式名稱與尺寸預設的標籤與說明
    ├── templates.json        # 範本的遊戲類型、風格類型、名稱與說明
    └── tags/
        └── <sheetId>.json    # 該分類的名稱、子分類名稱與每個標籤的顯示文字
```

語言中立的資料仍在 `config_sheets/`（結構、提示詞、尺寸數值），見 [詞庫與設定檔格式](CONFIG_SHEETS.md)。**送進繪圖模型的提示詞（英文）不會被翻譯**，只翻譯顯示給使用者看的標籤。

### `tags/<sheetId>.json`

```json
{
  "name": "鏡頭構圖",
  "categories": { "shot-size": "景別" },
  "subcategories": { "shot-size/shot-size": "景別" },
  "tags": { "close-up shot": "特寫鏡頭" }
}
```

- `categories` 以分類 id 為鍵；`subcategories` 以 `分類id/子分類id` 為鍵。
- `tags` 以**英文提示詞原文**為鍵，值是該語言的顯示文字。
- 英文（`en`）的標籤預設等於提示詞本身；介面在顯示文字與提示詞相同時，不會重複顯示提示詞。

## 執行時行為

- 語言選擇存於 `localStorage`（`language`）。首次開啟時依瀏覽器語言決定：`zh-*` → 繁體中文，`ja`、`ko` 對應各自語言，其餘使用英文。
- 缺少的 UI 字串依序後備：目前語言 → English → 繁體中文 → 顯示鍵名（並在 console 警告）。缺少的標籤顯示文字後備為英文提示詞；缺少的分類名稱後備為由 id 轉成的英文標題。
- 切換語言不會改變已選標籤、權重與提示詞內容，只會重繪顯示文字。
- HTML 使用 `data-i18n`（純文字）、`data-i18n-html`（僅允許 `<b>`、`<code>`、`<br>`）、`data-i18n-title`、`data-i18n-placeholder`、`data-i18n-aria-label`。
- JavaScript 使用 `t('鍵', { 參數 })`（等同 `I18N.t`）。字串中的 `{名稱}` 為占位符，翻譯時必須保留。
- 動態內容的模組監聽 `window` 的 `localechange` 事件重繪；需要語系資料的模組以 `I18N.addLoader(fn)` 註冊載入函式（`app.js`、`templates.js` 即採用此方式）。

## 翻譯工作流程

### 方式 A：直接編輯 JSON

編輯 `locales/<語言>/` 內的檔案，然後：

```bash
npm run i18n:check     # 檢查完整性
npm run i18n:table     # 重新產生對照表
```

### 方式 B：用試算表翻譯（建議給非工程人員）

```bash
npm run i18n:table     # 產生 docs/i18n/translation-table.csv 與 translation-table.md
```

1. 用 Excel／Google Sheets 開啟 `docs/i18n/translation-table.csv`（UTF-8，含 BOM）。
2. 欄位為 `scope, key, zh-TW, en, ja, ko`：`scope` 是檔案、`key` 是檔內路徑（以 `::` 分隔）。以 zh-TW 欄為原文，編輯你負責的語言欄。**不要改 `scope` 與 `key`。**
3. 存成 CSV（UTF-8），然後匯回：

   ```bash
   npm run i18n:import -- docs/i18n/translation-table.csv --dry-run   # 先預覽
   npm run i18n:import -- docs/i18n/translation-table.csv
   npm run i18n:check
   npm run i18n:table
   ```

匯入只會更新**已存在**的鍵；占位符（`{name}`）或標記（`<b>`、`<code>`、`<br>`）與 zh-TW 不一致、或出現未知的鍵時，會整批中止且不寫入任何檔案。空白儲存格會被略過。

`translation-table.md` 是同一份對照表的 Markdown 版，方便在 GitHub 上直接檢視，由工具產生，請勿手動編輯。

### 檢查項目（`npm run i18n:check`）

- 每個語言都有 `ui`、`profiles`、`templates` 與每個分類的 `tags/<sheetId>` 檔案，且鍵與 zh-TW 完全一致（缺少或多出皆為錯誤）。
- zh-TW 涵蓋 `config_sheets` 結構檔中的每個分類、子分類、標籤、模式、尺寸預設與範本，以及程式（`index.html`、`assets/js`）用到的每個 UI 鍵。
- 沒有空白翻譯；占位符與標記和 zh-TW 一致。
- 提示詞在不同分類中沒有重複（標籤以提示詞為鍵，必須唯一）。
- 警告：未使用的鍵、疑似未翻譯（與英文相同）的內容。

## 常見工作

### 新增語言

```bash
npm run i18n:add -- fr Français French
```

會以英文內容建立 `locales/fr/` 並登錄到 `locales.json`；語言選單會自動出現新語言。接著翻譯內容（方式 A 或 B）。建議同時新增 `README.<code>.md` 並在各 README 頂端的語言連結加入。

### 新增標籤、分類或範本

1. 在 `config_sheets/` 結構檔加入項目（見 [詞庫與設定檔格式](CONFIG_SHEETS.md)）。
2. 在**每個**語言的對應檔案加入顯示文字（至少先填 zh-TW 與 en）。
3. 執行 `npm run i18n:check`，缺少的鍵會逐一列出。

### 新增介面文字

1. 在 `index.html` 加上 `data-i18n="area.name"`，或在 JavaScript 呼叫 `t('area.name')`。
2. 在每個語言的 `ui.json` 加入該鍵。
3. 執行 `npm run i18n:check`。

## 翻譯慣例

- 保留 `{count}`、`{name}` 等占位符與 emoji；`<b>`、`<code>`、`<br>` 標記數量須與原文相同。
- 產品名稱（Midjourney、ComfyUI、Draw Things、Steam…）與參數名稱（Steps、CFG Scale、LoRA…）維持原文。
- 標籤的翻譯要簡短並貼近遊戲美術業界用語；日文、韓文標籤由機器輔助起稿，歡迎母語使用者校對後提交 PR。
